# هم‌درس؛ مدیریت سالن مطالعه

وب‌اپ فارسی و راست‌به‌چپ برای ثبت‌نام ماهانه، میزها، حضور و غیاب، شهریه و کارنامه. رابط با فونت‌های محلی **B Titr** و **B Koodak** ساخته شده است. برنامه با فهرست خالی شروع می‌شود و هیچ دانش‌آموز آزمایشی وارد اطلاعات اصلی نمی‌شود.

برای ساخت و دانلود نسخه ویندوز فقط با مرورگر، پس از انتقال سورس به گیت‌هاب، [راهنمای GitHub Actions](docs/windows-build-actions.md) را دنبال کنید. نام گردش‌کار **Build Hamdars Windows x64** است و با دکمه **Run workflow** اجرا می‌شود.

## نسخه اجرایی ویندوز

فایل `Hamdars-1.0.0-Windows-x64.exe` نسخه قابل‌حمل برای ویندوز ۱۰ و ۱۱ نسخه ۶۴ بیتی است. فایل را در پوشه دلخواه نگه دارید و دوبار کلیک کنید؛ نصب Node.js، اجرای دستور و اتصال اینترنت برای استفاده از برنامه لازم نیست. اولین باز شدن فایل ممکن است چند ثانیه طول بکشد. برنامه در یک پنجره مستقل باز می‌شود و با بستن پنجره، اجرای داخلی آن پایان می‌یابد.

اطلاعات سالن کنار فایل اجرایی ذخیره نمی‌شود؛ در پوشه `%APPDATA%\Hamdars` حساب ویندوز شما نگهداری می‌شود. جابه‌جایی یا جایگزینی فایل اجرایی، اطلاعات را پاک نمی‌کند. برای انتقال اطلاعات به کامپیوتر دیگر، از «تنظیمات و پشتیبان» نسخه پشتیبان بگیرید و در دستگاه جدید بازیابی کنید. باز کردن دوباره فایل، پنجره موجود را جلو می‌آورد و نسخه دومِ برنامه را اجرا نمی‌کند.

خروجی عکس، CSV و نسخه پشتیبان در نسخه دسکتاپ با پنجره انتخاب محل ذخیره دریافت می‌شوند. فونت‌ها و تمام فایل‌های لازم داخل برنامه قرار دارند. فایل اجرایی امضای تجاری دیجیتال ندارد.

برای بازسازی نسخه ویندوز از کد، بعد از `npm ci` این دستورها را اجرا کنید:

```bash
npx install-electron
npm run desktop:win
```

خروجی در پوشه `release/` ساخته می‌شود. `npm run desktop:prepare` فایل‌های وب و سرور دسکتاپ را می‌سازد؛ `npm run test:desktop` سرور بسته‌بندی‌شده، SQLite، رابط و فونت‌ها و ماندگاری داده را در موتور واقعی Electron با پایگاه موقت بررسی می‌کند. ساخت و آزمون در لینوکس، جای اجرای فایل نهایی روی ویندوز واقعی را نمی‌گیرد.

آزمون `node scripts/test-desktop-ui.mjs` پنجره واقعی Electron را با داده موقت باز می‌کند و ثبت‌نام، ولی، حضور ستاره‌ای، دریافت PNG و پشتیبان JSON و حفظ اطلاعات پس از بستن و بازکردن دوباره را بررسی می‌کند. در لینوکس از حالت headless Ozone استفاده می‌کند؛ فقط انتخاب محل ذخیره فایل در آزمون خودکار تعیین می‌شود و منطق برنامه واقعی اجرا می‌شود.

در محیط ابری حاضر، کش دانلود باید داخل مسیر قابل نوشتن باشد؛ نصب موتور دسکتاپ با `electron_config_cache=/workspace/.cache/electron node --use-env-proxy node_modules/electron/install.js` و ساخت با `XDG_CACHE_HOME=/workspace/.cache ELECTRON_BUILDER_CACHE=/workspace/.cache/electron-builder NODE_USE_ENV_PROXY=1 npm run desktop:win` انجام می‌شود. بررسی TLS و checksumهای رسمی Electron در دریافت‌ها فعال‌اند.

## اجرا

پیش‌نیاز: **Node.js 24 یا جدیدتر** و npm.

```bash
cd /workspace/apps
npm ci --cache /workspace/.npm-cache
npm run dev
```

اگر فایل برنامه را روی کامپیوتر خودتان اجرا می‌کنید، ابتدا Node.js 24 یا جدیدتر را نصب کنید، ترمینال را در پوشه استخراج‌شده برنامه باز کنید و `npm ci` و سپس `npm run dev` را بزنید. گزینه کشِ دستور بالا مخصوص همین محیط ابری است.

در حالت توسعه، رابط روی پورت `5173` و API روی `3001` اجرا می‌شوند. Vite درخواست‌های API را به سرور محلی هدایت می‌کند. برای اجرای نسخه ساخته‌شده:

```bash
npm run build
npm start
```

نسخه ساخته‌شده و API هر دو روی پورت `3001` سرو می‌شوند. سرور به‌صورت پیش‌فرض فقط به `127.0.0.1` متصل است. `PORT`، `HOST` و `DATABASE_PATH` قابل تنظیم‌اند. این نسخه برای استفاده خصوصی یک سالن است و ورود کاربران و سطح دسترسی ندارد؛ انتشار روی اینترنت به احراز هویت، HTTPS و نگهداری امن اطلاعات نیاز دارد.

## گردش کار

1. از «تنظیمات و پشتیبان»، نام سالن، تعداد میزها، شهریه پیش‌فرض و قانون نمره را تعیین کنید.
2. ماه و سال شمسی را بالای صفحه انتخاب کنید. در «دانش‌آموزان»، مشخصات دانش‌آموز و ولی، شماره میز و شهریه را ثبت کنید. یک میز در هر ماه به یک نفر اختصاص دارد. ثبت‌نام قبلی‌ها و انتقال ثبت‌نام ماه قبل نیز در دسترس است.
3. در «حضور و غیاب»، تاریخ شمسی و شیفت **صبح یا عصر** را انتخاب کنید. هر شیفت دقیقاً **چهار زنگ** دارد. ابتدا نام و تماس مسئول و زمان زنگ‌ها را ثبت کنید؛ سپس جلوی هر نام ستاره بزنید. حضور همه افراد در یک زنگ را نیز می‌توان با دکمه «همه» ثبت یا لغو کرد.
4. دکمه «خروجی تصویر»، فرم کامل همان روز و شیفت را با نام سالن، تاریخ، مسئول، میزها، چهار زنگ و جمع حاضرین به **PNG** تبدیل می‌کند. اطلاعات خانوادگی و شهریه در تصویر حضور نمایش داده نمی‌شود.
5. در «انضباط و امتیاز»، تخلف یا امتیاز مثبت با تاریخ، عنوان، مقدار و توضیح ثبت کنید. موارد پیشنهادی قابل انتخاب‌اند و عنوان دلخواه هم وجود دارد.
6. در «شهریه و پرداخت»، پرداخت کامل یا قسطی و تاریخ و یادداشت آن را ثبت کنید. وضعیت تسویه و مانده خودکار محاسبه می‌شود. پرداخت اشتباه از سوابق قابل حذف است. مبلغ‌ها **تومان** هستند.
7. در «گزارش ماهانه»، ساعت مطالعه هر دو شیفت، امتیازهای مثبت و منفی و نمره از ۱۰۰ نمایش داده می‌شوند. کارنامه تک‌نفره با ریز حضور و تصویر قابل دریافت است؛ جدول‌ها خروجی CSV مناسب اکسل دارند.

## ساعت مطالعه و نمره

مدت پیش‌فرض هر زنگ ۹۰ دقیقه است و هنگام ثبت شیفت می‌توان زمان‌ها را تغییر داد. فقط زنگ‌های ستاره‌خورده در ساعت مطالعه شمرده می‌شوند. زمان زنگ‌ها در یک روز نباید با هم تداخل داشته باشد. تغییر ساعت یک شیفت، ساعت مطالعه حضورهای همان شیفت را دوباره محاسبه می‌کند.

قانون اولیه قابل تغییر در تنظیمات:

- هدف مطالعه ماهانه: ۱۲۰ ساعت؛ سهم حضور: ۸۰ نمره.
- هدف امتیاز مثبت: ۲۰ امتیاز؛ سهم تشویقی: ۲۰ نمره.
- هر امتیاز منفی: کسر ۱ نمره.
- نمره نهایی: مجموع بخش حضور و تشویقی منهای کسر انضباطی، گرد شده و محدود به صفر تا صد.

هر بخش تا سقف سهم خودش محاسبه می‌شود. تنظیمات فعلی روی گزارش همه ماه‌ها اعمال می‌شوند. شهریه در نمره تأثیر ندارد.

## نگهداری اطلاعات

اطلاعات در `data/study-hall.sqlite` ذخیره می‌شوند و با رفرش مرورگر از بین نمی‌روند. این پوشه در Git ثبت نمی‌شود. فایل‌های SQLite را هنگام اجرای برنامه دستی جابه‌جا نکنید؛ برای انتقال از دکمه «دریافت نسخه پشتیبان» استفاده کنید.

پشتیبان JSON شامل تمام داده‌ها و تنظیمات است. بازیابی فقط پس از تأیید کاربر و اعتبارسنجی کامل انجام می‌شود و تمام اطلاعات فعلی را جایگزین می‌کند. نسخه پشتیبان حاوی اطلاعات شخصی است و باید در محل امن نگهداری شود. ثبت‌نام دارای سابقه حضور، پرداخت یا امتیاز حذف نمی‌شود تا سابقه از دست نرود.

## بررسی‌ها

```bash
npm run build
npm test
npm run test:e2e
```

`npm test` منطق ثبت‌نام، میز، هر هشت زنگ، شهریه، نمره، تاریخ شمسی، پشتیبان و ماندگاری SQLite را بررسی می‌کند. آزمون مرورگر به Chromium نیاز دارد؛ مسیر پیش‌فرض `/usr/bin/chromium` است و با `CHROMIUM_PATH` عوض می‌شود. آزمون مرورگر از پایگاه داده موقت استفاده می‌کند، گردش کار واقعی و دانلود PNG را می‌آزماید و تصاویر بررسی را در `test-results/` می‌گذارد؛ اطلاعات اصلی سالن تغییر نمی‌کند. پیش از آن `npm run build` را اجرا کنید.

منبع و اطلاعات مجوز فونت‌ها در `public/fonts/README.md` ثبت شده‌اند.
