# ساخت و دریافت نسخه ویندوز از مرورگر

این روش به نصب ابزار برنامه‌نویسی روی رایانه شما نیاز ندارد. ساخت برنامه روی رایانه ویندوز GitHub انجام می‌شود و فایل نهایی را از مرورگر دریافت می‌کنید. سورس و فایل `.github/workflows/windows-build.yml` باید ابتدا روی شاخه `main` مخزن `h4d2admin-art/apps` قرار گرفته باشند. تا زمانی که Push موفق نشده، این گردش‌کار در گیت‌هاب قابل اجرا نیست.

## دریافت برنامه

1. وارد حساب گیت‌هابی شوید که به مخزن خصوصی دسترسی دارد و [مخزن همدرس](https://github.com/h4d2admin-art/apps) را باز کنید.
2. زبانه **Actions** را باز کنید. اگر گیت‌هاب پیام فعال‌سازی Actions نشان داد، آن را برای همین مخزن فعال کنید.
3. در فهرست سمت چپ، **Build Hamdars Windows x64** را انتخاب کنید.
4. دکمه **Run workflow** را بزنید، شاخه **main** را انتخاب کنید و اجرای آن را تأیید کنید.
5. وارد اجرای تازه شوید و منتظر علامت سبز موفقیت بمانید. در صورت خطا، بخش قرمز را باز کنید؛ فایل ساخته‌شده فقط پس از موفقیت تمام مراحل ارائه می‌شود.
6. پایین همان صفحه، در بخش **Artifacts**، روی **Hamdars-1.0.0-Windows-x64** کلیک کنید. شماره نسخه با نسخه پروژه تغییر می‌کند.
7. فایل ZIP را دانلود و با **Extract All** باز کنید. داخل آن `Hamdars-1.0.0-Windows-x64.exe` و `SHA256SUMS.txt` قرار دارد.
8. فایل EXE را روی ویندوز ۱۰ یا ۱۱ نسخه ۶۴ بیتی اجرا کنید. این خروجی **قابل‌حمل (Portable)** است و نصاب مرحله‌ای ندارد؛ Node.js جداگانه نیاز نیست.

آدرس مستقیم صفحه گردش‌کار، پس از Push موفق: [Build Hamdars Windows x64](https://github.com/h4d2admin-art/apps/actions/workflows/windows-build.yml).

دانلود Artifacts به ورود به گیت‌هاب و دسترسی به مخزن نیاز دارد. فایل هر اجرا تا **۳۰ روز** نگهداری می‌شود؛ آن را روی رایانه خود ذخیره کنید. پس از انقضا می‌توانید دوباره **Run workflow** را بزنید. محدودیت مصرف Actions حساب گیت‌هاب و تنظیمات سازمان یا مخزن ممکن است مانع اجرا شوند؛ جزئیات در همان صفحه اجرای گیت‌هاب نمایش داده می‌شود.

خروجی در تنظیمات فعلی امضای ناشر ویندوز ندارد.

## بررسی اختیاری فایل

فایل `SHA256SUMS.txt`، اثر انگشت همان EXE را دارد. اگر نیاز به بررسی دانلود داشتید، در PowerShell داخل پوشه استخراج‌شده دستور زیر را اجرا کنید و نتیجه را با فایل متنی مقایسه کنید:

```powershell
Get-FileHash .\Hamdars-1.0.0-Windows-x64.exe -Algorithm SHA256
```

## مراحل واقعی ساخت

گردش‌کار فقط با درخواست دستی `workflow_dispatch` اجرا می‌شود. به صورت خودکار با Push اجرا نمی‌شود و هیچ Releaseای منتشر نمی‌کند. مجوز آن فقط `contents: read` است؛ توکن یا رمز جدیدی لازم نیست.

- اجرای `windows-latest` و نصب Node.js 24 نسخه x64.
- نصب دقیق وابستگی‌های قفل‌شده با `npm ci`.
- دریافت Electron نسخه قفل‌شده پروژه با `npx --no-install install-electron`؛ Electron 44.9.0 نصب خودکار `postinstall` ندارد. کنترل HTTPS و checksum فعال می‌ماند.
- اجرای `npm test` برای آزمون‌های برنامه در `tests/*.test.ts`.
- اجرای `npm run desktop:win -- --publish never` طبق `electron-builder.json`: بررسی TypeScript، ساخت رابط و سرور محلی، سپس بسته‌بندی خروجی Portable x64 در `release/`.
- اجرای `npm run test:desktop` روی Electron ویندوز برای بررسی SQLite، API، رابط و فونت فارسی، ذخیره پایدار و پشتیبان با داده موقت آزمون.
- بررسی هدر PE32+ x64 برنامه واقعی داخل `release/win-unpacked`، محاسبه SHA256 فایل Portable، و بارگذاری فقط EXE و `SHA256SUMS.txt` در Artifacts.

این بررسی‌ها، آزمون نصب یا کاربری کامل روی رایانه شخصی شما نیستند. فایل‌ها و داده‌های دانش‌آموزان در ساخت استفاده نمی‌شوند؛ سورس پروژه و داده‌های موقت آزمون کافی هستند.

گردش‌کار قدیمی **Download existing Hamdars Windows EXE** مسیر جداگانه‌ای برای دریافت فایل یک Release موجود است؛ آن را برای ساخت تازه انتخاب نکنید. آزمون `tests/windows-delivery.test.mjs` هم مخصوص همان خروجی ازپیش‌موجود و ابزار تحویل آن است و بخشی از این ساخت تازه نیست؛ پوشه `release/` عمداً در Git ذخیره نمی‌شود.
